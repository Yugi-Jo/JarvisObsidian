## ROOT CAUSE FOUND: Google OAuth failures

Investigated mid-session on Joel's insistence that he'd already fixed it. He was partly right — setup work was done — but the app is in the wrong state.

**Evidence:**
- OAuth client: `422217702558-scbcjcqfhtoblic9bg05comf7n5pnar4` (project `cosmic-keep-511806-e0`)
- Both credential files (`.hermes/google_token.json` and `.config/gws/credentials.json`) use that **same client**, both fail refresh with `invalid_grant: Token has been expired or revoked`
- Token access-expiry stamp: `2026-10-28T02:04:49Z`. Setup was 2026-10-26 — it died roughly 2 days after.
- Tonight's re-auth returned **`access_denied` — "It's currently being tested and it hasn't been verified by Google."**
- The Oct 26 session recorded in memory that the project was **"published to Production, so tokens won't expire every 7 days"** — that note was lost in a later consolidation, and the evidence contradicts it.

**Conclusion:** the OAuth consent screen for `cosmic-keep-511806-e0` is **still in Testing mode**, not Production. That one fact explains both symptoms — Testing mode kills refresh tokens after ~7 days (the revocation), and only listed test users can authorise (the `access_denied`).

**Fix (Google Cloud Console, project `cosmic-keep-511806-e0`):**
- APIs & Services → OAuth consent screen → **Publish app** to Production (permanent refresh tokens), *or* add the account under **Audience → Test users** as a stopgap (still expires every 7 days).
- Then re-auth. Sensitive scopes on an unverified app show an "unverified app" warning — Advanced → proceed.
- Fold the YouTube scopes into the same re-auth so YouTube Studio needs only one round.
