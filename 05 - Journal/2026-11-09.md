## Hindsight long-term memory outage — diagnosed and fixed

**It had never worked.** Not an outage that started partway — the bank was never functional since setup, so no memories were lost; it simply began empty.

| Evidence | Timestamp |
| --- | --- |
| Hindsight configured (`~/.hermes/hindsight/config.json`) | 2026-10-16 23:03 |
| Provider reported unavailable — `hindsight-client`/`hindsight-embed` packages missing | 2026-10-16 23:34 |
| First hard failure: `Failed to start the Hindsight daemon for profile 'hermes'` | 2026-10-20 15:47:55 |
| Fixed (daemon booted successfully, first fact ever stored) | 2026-11-09 08:03 |

- Error volume logged over the dead window: **4279** daemon-start failures, **1309** recall failures, **108** retain failures.
- **Root cause:** the embedded daemon is launched as `uvx hindsight-api@0.10.3`, but `uvx` was not on `PATH`. Hermes ships uv/uvx in `~/.hermes/tools/uv-0.12.3-linux-arm64/` — that directory is not on `PATH`.
- **Fix:** symlinked `uv` and `uvx` into `~/.local/bin` (which is on `PATH`).
- **Downtime:** ~23 days from configuration, ~20 days from the first hard failure.
- Writes are async — `retain` returns "queued" seconds later, but the fact only becomes findable once the fact-extraction stage finishes (2–4 min on a cold start). Verified by recall, not by the "queued" response.
- Fix documented in the `hermes-agent` skill: `references/troubleshooting.md`.

## Prevention (so this can't silently die again)

- **Version-proof launcher:** `~/.local/bin/uv` and `~/.local/bin/uvx` are now pass-through shims (canonical copies in `~/.hermes/scripts/shims/`) that glob for the newest bundled uv at call time. The old versioned symlink would have broken on the next uv upgrade. Verified by renaming the bundled dir and confirming the shim still ran.
- **Watchdog:** cron `hindsight-memory-healthcheck` (every 6 h, `~/.hermes/scripts/hindsight_healthcheck.sh`, no-agent). Silent when healthy. Self-heals a missing shim or a missing reasoning-off key; alerts only on real breakage (launcher gone, extraction model not answering, daemon unhealthy, provider unavailable).
- **All three paths tested:** shim removed → self-healed; reasoning key removed → self-healed; model broken → alert fired with HTTP 400 detail.
